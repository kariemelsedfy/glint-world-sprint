## Working behavior

`GizaScene({ definition, seed, quality })` no longer uses the shared graybox. It renders a warm desert
diorama entirely from `definition`:

- Ground apron in Giza sand (`#e8b969`), pale stone paths from `definition.roads`.
- Round flagstone pads at the spawn plaza (teal centre) and at all nine sockets so pickup spots read from the camera.
- Every blocker rect is dispatched to a scenery builder that stays inside its rect:
  `great-pyramid` (26-unit four-sided pyramid with lighter lower course), `sphinx` (reclining lion facing
  south with paws, chest, blue nemes, gold brow band), `market` (2×3 stalls with seeded canopy colours),
  `queen-pyramid-a/b` (9-unit pyramids), `oasis-north/south` (pool ringed by palms), `village`
  (flat-roofed clay houses, dome, slim tower). Unknown blocker ids fall back to a clay block so collision and
  visuals never disagree.
- Seeded cosmetics (via `@/shared/seed`, independent stream per group): 60 instanced rocks kept ≥3 units from
  blockers, 1.5 from roads, 5 from sockets and 8 from spawn; dunes and a low clay skyline placed outside `bounds`.
- `quality: 'low'`: same layout, drops rocks, horizon, stall poles, pyramid base course, sphinx details and
  palm frond count. No React state changes per frame; no `useFrame`.

### Performance pass (second PR)

The scene is now baked once per `(definition, seed, quality)` in a `useMemo`: every prop is a transformed clone
of one of 8 low-segment source geometries, merged with `mergeGeometries` into **one geometry per material**.
Result: ≤22 draw calls in `standard` (one per material actually used + one `InstancedMesh` of 60 rocks),
~17 in `low`, versus ~270 individual meshes before. Segment counts were cut (cylinder 10→7, disc 24→14,
sphere 12×8→8×5), horizon dunes 26→14, skyline 18→14, palms 8→7 per oasis, fronds 6→5. No transparency,
shadows, lights or per-frame work are added by the scene; merged geometries are disposed when rebuilt.

### Perf pass 2 (seventh PR, `definition.ts` untouched)

Measured with the perf-spec method (5 s rAF sample after 1 s warm-up, SwiftShader, 1280×720, Giza
after fly-in, `npm run build && npm run preview`) on the A4 box. Giza with the scene returning `null`
is 60 fps here, so everything below is scene cost.

| Giza                 | before (6a2cb8b) | after         |
| -------------------- | ---------------- | ------------- |
| standard mean        | 23.5 ms / 42.5 fps | 19.8–20.6 ms / 48.6–50.4 fps |
| low mean             | 17.3 ms / 57.8 fps | 16.7 ms / 60 fps (vsync cap) |
| draw calls std / low | 21 / 15          | 21 / 15       |
| triangles std / low  | 30.3k / 5.7k     | 24.1k / 5.3k  |

Changes: ground/tinted-hero/shadow/ink buckets moved to `MeshBasicMaterial` with the app lighting
baked into the vertex colours (`BAKED_LIGHT`, tuned so the sand pixel colour matches the previous
Lambert result within ~5/255), so the full-screen ground layer and every outline skip per-fragment
lighting; props with max scale < 1.4 no longer emit an ink copy; shadow discs 14 → 10 segments; wind
streaks 40 → 24, rocks 60 → 48. Silhouettes, sockets and collision unchanged.

overhead, which SwiftShader does not model.

## Provenance and limitations

All geometry is procedural Three.js primitives written in this session (Devin); no third-party assets.
Colours from `docs/ART_DIRECTION.md`. Known limitations: the pyramidion collectible is rendered by A1's
`Collectibles`, not here; no shadows (consistent with Paris graybox lighting); the horizon skyline is only
along the south edge; the arrival view shows the Great Pyramid only at the frame corner because the
camera offset is fixed by A0.
